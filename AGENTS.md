# AGENTS.md

## Commands

Node and pnpm versions are pinned in `mise.toml`; use pnpm.

```bash
pnpm dev          # Astro dev server
pnpm build        # static build into dist/
pnpm check        # wrangler types + astro check + tsc -p worker (the CI gate)
pnpm cf:preview   # build and serve dist/ through Wrangler, as Cloudflare does
node scripts/og-image.mjs   # regenerate public/og.png (name/role/avatar changes)
```

There are no tests or linter. `pnpm check` is what Workers Builds runs before `pnpm build`, so run it after changes. `worker-configuration.d.ts` is generated by `wrangler types` and gitignored.

API keys for local builds go in `.env` (see `.env.example`); `.envrc` exports it. Without keys the build still works and simply omits the data sections.

## Architecture

A single-page static Astro site (no client-side JavaScript, no framework components, Tailwind v4) served as static assets by a Cloudflare Worker.

**Build-time data.** The homepage's "Recently listening" (Last.fm) and "Recently starred" (GitHub GraphQL) sections are fetched at build time. `src/lib/data.ts` `getPageData()` memoizes one fetch per build and is shared by both `src/pages/index.astro` and `src/pages/index.md.ts`. A section with no data is `null` and is left out of the page.

**Fetch failure semantics** (`src/lib/strict.ts`): API fetches go through `buildTimeFetch`, which returns `null` on a missing key or error locally, but throws when `STRICT_FETCH=true` (set in Workers Builds) so a broken rebuild keeps the last good deploy live. Errors log only the message because URLs can contain API keys. Album link enrichment (`src/lib/albumLinks.ts`, MusicBrainz → Wikidata/Wikipedia and Spotify) is best-effort and never fails the build, even in strict mode; it runs sequentially to respect MusicBrainz's rate limit.

**Two renderings of one page.** `src/pages/index.md.ts` emits `/index.md`, a Markdown version of the homepage for agents. Any content change to the homepage (sections, links, blurbs) must be mirrored there. Shared constants live in `src/lib/site.ts` and `src/lib/links.ts`; the bio is `src/content/bio.md`, used by both.

**Hosting** (`wrangler.jsonc`, `worker/`): `dist/` is served as Worker static assets. `worker/index.ts` only forwards unmatched requests to the assets 404 page and, on a daily cron (06:00 UTC), POSTs to a Workers Builds Deploy Hook (`DEPLOY_HOOK_URL`) to rebuild with fresh data. Deploys happen via Workers Builds on push to `main`; build variables and secrets live in the Cloudflare dashboard (table in `README.md`). The worker has its own `tsconfig.json` and is excluded from the root one.

**Constraints to keep in mind:**
- `public/_headers` sets a CSP of `default-src 'none'` with no scripts allowed and `img-src 'self'`; adding JS or external images requires updating it. Remote images (e.g. the GitHub avatar) must be optimized through `astro:assets` (allowed domains in `astro.config.mjs`).
- `trailingSlash: "never"` with `build.format: "file"` preserves the old Next.js URLs; redirects are in `public/_redirects`.
- Imports use the `@/*` → `src/*` alias.
